# LTE 网优 KPI 异常检测工具（Python + Pandas）

面向网优日常巡检：把网管导出的小区级小时 KPI，一条命令完成「清洗 + 异常判定 + 出标准工单」，替代人工在 Excel 里逐个小区、逐个时段筛查。

## 项目背景

网优每天要从网管导出几百个小区、上千个时段的 KPI，人工找出「哪个小区、哪个指标、从几点到几点不合格」，再整理成工单派给外场。这件事本身不难，但有三个绕不过去的问题：

- **慢**：全量数据在 Excel 里做一次透视要几分钟，想换个考核口径再筛一遍又要几分钟；
- **口径不统一**：今天用 95%、明天用 94%，工单数据前后没法比；
- **容易漏**：想从一张几万行的表里挑出「连续 3 小时以上不达标」的片段，人眼基本做不到。

这个工具把「清洗 → 规则判定 → 出工单」三步固化成一条命令，把人的时间从「找异常」挪到「判断异常、派单处理」上。单次运行 2 秒内跑完，20 个小区的样例数据产出 102 张可直接派单的工单。

## 技术栈

- Python 3.10+，Pandas（开发与实测环境：Python 3.12 + pandas 3.0.1）
- 纯业务规则实现：绝对阈值比较 + 当日均值同比 + 连续时长计数，**不使用任何机器学习或统计模型**，结论可解释、可逐条追溯
- CSV 输入输出，UTF-8-BOM 编码，Excel 双击直接打开不乱码

## 核心功能

全部逻辑在一个文件 `kpi_anomaly_analysis.py` 里，一次运行完成清洗、检测、统计、导出：

**1. 数据清洗**：删空值行（采集失败）、删重复行（重复上报）、多格式时间统一、过滤指标负值（计数器回卷）、只保留 6 个核心字段。

**2. 三条检测规则**（现网日常口径）：

| 规则 | 判定条件 | 工单类型 | 等级 |
| --- | --- | --- | --- |
| R1 绝对阈值 | 接入成功率 < 95%，掉话率 > 2%，切换成功率 < 92% | 绝对阈值 | 重要 |
| R2 波动 | 单小时指标低于该小区**当日**均值 70%（掉话率方向相反，高于 130%） | 波动 | 一般 |
| R3 持续故障 | 同一小区**连续 ≥ 3 小时**触发 R1 | 持续故障 | 紧急 |

工程上做了三条约束：连续 3 小时以上的片段只出「持续故障」单，不再重复出「绝对阈值」单；已被 R1 命中的小时不再参与波动判定；采集中断会把片段截断，不会把断开的两段拼成一个「连续故障」。

**3. 输出**：7 列标准工单（小区ID / 异常开始时间 / 异常结束时间 / 异常类型 / 异常指标 / 指标数值 / 严重等级），外加三项统计——三类异常占比、异常时段分布、异常小区 Top10。

**样例数据实测结果**（20 小区 × 14 天）：102 张工单，紧急 13 / 重要 7 / 一般 82。值得注意的是**数量与影响倒挂**：持续故障只占工单数的 12.7%，却占了劣化总时长的 65.1%——真故障只有十来张单，剩下八十多张是单小时抖动，如果按告警条数排序会看错重点。异常时段集中在 18–20 点忙时，占 37.2%。

**一点使用提醒**：波动规则对掉话率最敏感（基准值只有 0.5% 左右，130% 的相对阈值很容易被一次掉线触发），如需减少告警量，可在脚本顶部把 `WAVE_RATIO_UPPER` 调大，或要求波动片段连续 2 小时以上。成功率类指标的 70% 阈值实际上高于绝对阈值（99% × 70% ≈ 69%，而 95% 早就拦住了），所以波动基本只对掉话率生效——这是规则本身的特点，不是 bug。

## 数据说明

仓库内两个 CSV 是**可直接运行的样例数据**（按现网统计特征仿真，含弱覆盖、干扰、退服等故障注入），不上传原始带脏数据的导出文件：

- `data/clean_lte_kpi.csv`：20 个小区 × 14 天 × 24 小时，6581 行，已清洗，可直接作为输入；
- `data/anomaly_work_order.csv`：用上面的数据跑出来的工单，可用于对照验证。

| 字段 | 业务含义 | 单位 | 现网典型范围 |
| --- | --- | --- | --- |
| 小区ID | 小区唯一标识 | — | — |
| 时间 | KPI 统计起始时刻，小时粒度 | — | — |
| 接入成功率 | 终端发起接入并成功建立连接的比例 | % | 98.5–99.8 |
| 掉话率 | 通话建立后异常释放的比例 | % | 0.2–1.0 |
| 下行吞吐量 | 单用户下行平均速率 | Mbps | 20–120 |
| 切换成功率 | 移动中切换成功的比例 | % | 95–99 |

**换成真实数据**：只改 `kpi_anomaly_analysis.py` 顶部的两处——`RENAME_MAP`（把导出文件的列名映射成标准列名，如 `接入成功率(%)` → `接入成功率`）和 `ABS_RULES`（按当地考核口径调三个门限），其余逻辑不用动。文件是 Excel 时，把 `pd.read_csv` 换成 `pd.read_excel(..., sheet_name=...)` 即可。

> 说明：本项目最初想直接用 CellPAD 论文的 KPI 数据，但核实后确认其只开源了检测框架源码，论文字段的运营商数据从未公开，因此改用按现网分布仿真的样例数据，并把数据接入点做成可替换的。

## 使用方法

```bash
pip install pandas
python kpi_anomaly_analysis.py                    # 默认读 data/clean_lte_kpi.csv，工单写回 data/
python kpi_anomaly_analysis.py my_kpi.csv         # 也可以指定输入文件
```

PyCharm 里直接右键 Run 即可，脚本用 `__file__` 定位路径，不依赖运行目录。

### 工单输出示例

```
小区ID,异常开始时间,异常结束时间,异常类型,异常指标,指标数值,严重等级
460-01-450103-1,2024-03-03 15:00,2024-03-05 02:00,持续故障,接入成功率,93.6,紧急
```

## 可迁移场景

这套流程的本质是「多维度时序数据 + 阈值/同比/连续时长判定 + 标准工单输出」，换个字段映射就能复用：

**1. 运营商网优 KPI 日常巡检**（主要场景）
把 `RENAME_MAP` 改成当地网管的列名、`ABS_RULES` 换成省公司考核门限，就是每日巡检的自动化前置环节。挂到 Windows 任务计划或 crontab 每天 6:00 跑一次，上班直接拿当天待排查清单。

**2. 路测（DT）数据批量汇总**
路测导出的是采样点级的 RSRP/SINR/PCI 记录，把「小区 ID」换成「测试路段 + 经纬度栅格」、把「小时」换成「50 米栅格」，同一套连续段切分逻辑就能输出弱覆盖路段、切换失败路段清单，直接用于拉网报告。

**3. 基站性能异常排查**
字段换成退服时长、传输闪断次数、CPU/内存利用率、板卡告警数，规则换成「利用率 > 85% 持续 3 小时」「退服次数 > 0 即出单」，就是一张基站健康度巡检表。

凡是「多个对象 × 时间序列 × 有明确合格线」的场景（机房温湿度告警、电费异常筛查、传输误码率巡检）都能直接套。
